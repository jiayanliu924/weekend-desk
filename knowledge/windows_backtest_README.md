# 休市窗口回测（windows_backtest）说明

`desk/windows_backtest.py` 把所有"参考市场关着、但 Hyperliquid xyz 永续还在交易"的时段放到同一张表里，
用同一套度量（锚价 / 决策价 / 重开价）和同一套成本口径算反向与顺向的净收益，最后给窗口排名。
它是 `desk/overnight_backtest.py`（假设 #23，美股隔夜）的推广；两者共用 `desk/backtest_lib.py`
（K 线抓取/缓存/取价、资金费率、盈亏统计）。

备忘 7.2 的约束不变：**事后回补的 K 线只能用于粗略探索，不计入正式成绩。** 这个脚本回答的是
"哪些窗口值得拿模拟盘去正式验证"，不是"哪些窗口已经证明能赚钱"。

## 一、五类窗口

| 韩股隔夜 / 周末 / 假日 | SMSN | KRX 交易日 15:30 KST | 次交易日 08:45 KST | 09:00 KST | 09:05 KST | 首尔无夏令时；KRX 2025/26 假日手写（含 2026-10-09 韩文日） |
| Brent 日间休市 | BRENTOIL | 周一至周四 18:00 ET | 19:45 ET | 20:00 ET | 20:05 ET | ICE Brent 每天休两小时 |

"隔夜 / 周末 / 假日"按收盘日到重开日的间隔区分：隔 1 天 = 隔夜；周五隔 3 天 = 周末；其他 = 假日。

第五项"资金费率 carry"不是单独的窗口，而是每个窗口的一列调整项（见第三节）。

## 二、每个窗口 × 合约算什么

- `dev_bps`：决策价 / 锚价 − 1。锚价 = 底层收盘前最后一根 K 线的收盘价；决策价 = 决策时刻前最后一根 K 线的收盘价。
- `y_bps`：重开价 / 锚价 − 1。重开价 = 平仓时刻之后第一根 K 线的收盘价（15 分钟 K 线时就是重开后第一根）。
- `move_from_dec_bps`：重开价 / 决策价 − 1，这才是一笔交易真正吃到的变动。
- **反向（fade）**：|dev| > 门槛时按 −sign(dev) 开仓，赌偏离被抹掉。净收益 = −sign(dev)·move − 全额手续费。
- **顺向（follow）**：按 +sign(dev) 开仓，赌偏离被确认。净收益 = +sign(dev)·move − 全额手续费。
- 全额手续费 = 吃单 9 + 挂单 3 + 半点差估计（默认 2，`--half-spread` 可改，或在 config `[costs]` 加 `half_spread_bps`）= 14 bps；
  出手门槛 = 手续费 + edge_buffer（2）= 16 bps。
- 每组给：窗口数 n、笔数、命中率（毛收益 > 0 的比例）、胜率（扣费后 > 0 的比例）、平均净 bps/笔、累计净 USD（每笔 $1000 名义）、最差一笔、最大回撤。
- 门槛扫描：14 / 25 / 50 / 100 / 200 bps 各算一遍，看"只在偏离很大时出手"是否更好。

缺 K 线时最多向前/向后找 4 根；再找不到这个窗口就丢掉（不会用错根）。

## 三、资金费率 carry

- 数据：`fundingHistory`（每小时一条）→ 本地缓存 `data/backfill/funding_<coin>.parquet` → 收集器原始流 `hl_ctx` 里的 `funding` → 都没有就按 0。
- `carry_bps` = (决策, 平仓] 内结算的费率之和 × 1e4，站在我们这一侧：费率为正时空头收、多头付。
- 排名表里"含 carry USD"= 净收益 + carry。决策到平仓只有 20 分钟，往往跨不到整点结算，所以这一列大多接近净收益本身。
- 汇总表里"休市期空头 carry bps"= 从关门一直拿到平仓的费率之和的均值。它不进盈亏，只回答"整段休市里哪一边更挤"：
  数值大且为正 = 多头在付钱、仓位挤在多头一侧，是反向做空的顺风，也是插针风险信号（见 desk/mark.py 的说明）。

## 四、怎么在服务器上跑

沙盒 / 本机连不上 `api.hyperliquid.xyz`（代理 403），脚本会检测到并打印提示，然后尝试本地缓存。要出真结果：

```bash
# 在能访问 Hyperliquid 的 bot 服务器上
cd ~/weekend-desk
python3 -m desk.windows_backtest --since 2026-04-01            # 默认每笔 $1000、半点差 2 bps
python3 -m desk.windows_backtest --since 2026-04-01 --notional 2000 --half-spread 3 --out data/reports/windows_2026Q2.md
```

- 输出：`data/reports/windows_backtest.md`（同时打印到终端）。
- K 线缓存到 `data/backfill/candles_<coin>_15m.parquet`，费率缓存到 `data/backfill/funding_<coin>.parquet`。
  把 `data/backfill/` 整个目录拷回本机，再跑同一条命令就能离线重算（取价、门槛、名义金额都能改）。
- `--since` 决定抓多少天 K 线和算哪些窗口；Hyperliquid 15 分钟 K 线一次最多 5000 根，脚本自动翻页。
- 同一台机器上 `python3 -m desk.overnight_backtest` 存的缓存文件名一样，两边互通。

## 五、怎么读排名

报告结构：数据来源 → 中文结论 → 窗口排名（窗口 × 合约 × 方向）→ 按窗口类型汇总 → 门槛扫描 → 口径说明。

1. 先看"结论"的第二条：有没有任何组合同时满足 **平均净 > 0、胜率 ≥ 50%、样本 ≥ 5 笔**。没有就说明休市偏离整体不够覆盖 14 bps 往返成本，别往下想了。
2. 排名表按"平均净 bps/笔"从高到低，同分看累计 USD。但样本 1–3 笔的行（事件窗、假日窗常见）排前面不说明问题，先看"笔数"列。
3. 同一窗口的反向和顺向互为镜像（毛收益相反、手续费一样），两者都亏说明偏离幅度本身不够，不是方向选错。
4. 汇总表的 β(y~dev)：0 = 偏离全被抹掉（反向的世界），1 = 偏离全被确认（顺向的世界），0.5 上下 = 看不出方向。
5. 门槛扫描：如果 50 / 100 bps 门槛下平均净明显好于 14 bps，说明边际集中在大偏离上，正式验证时就只在大偏离出手。
6. "最差一笔"和"最大回撤"是给首损规则（config `[risk]`）用的：某类窗口单笔最差超过 −200 bps 的，要按 `worst_adverse_bps` 缩仓。

## 六、已知局限

- 回补 K 线没有盘口，手续费按半点差估计，没算滑点；真实成交要用模拟盘复核。
- 美股 09:15 ET 已在盘前时段，偏离里可能混着盘前真实信息；overnight_backtest 有 04:00 对照版本。
- KRX 和 ICE 假日是手写表，每年初要对一次官方日历。
- 事件窗的"锚 = 事件前 4 小时"是一个选择，不是定论；只有十几个事件样本，只能看方向。
- 测试（`tests/test_windows.py`）用确定性的合成 K 线验证时间对齐和数学，不验证任何市场结论。
