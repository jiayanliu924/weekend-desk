# 期权研究室：agents 赛马 + 自我迭代循环（设计，Opus，2026-10-25）

目标：让 agents 自己不断提期权策略、用**真实报价**回测、按成绩奖惩和淘汰、从失败里改进，
同时不把"试了几百次总有一个碰巧好看"当成本事。借鉴（见 knowledge/open_source_tools_R3.md）：
- Microsoft RD-Agent：提方案 → 代码实现 → 回测 → 反馈 → 下一轮；全程留研究日志；只有超过"当前最好"才晋级。
- TradingAgents：多头/空头/风控分角色辩论；事后按真实结果写反思，下一轮读反思。
- López de Prado：试验次数越多门槛越高（Deflated Sharpe）；PBO（回测过拟合概率，CSCV 法）；保留只开一次的金库数据。

## 0. 现状和要改的
- 现有 18 人赛马（desk/arena.py、desk/agents.py）机制保留：代码打分、冠军/淘汰/变异、playbook。
- **问题**：算法室给期权方案打分用 desk/algolab.py `backtest_options` 的 DVOL 近似公式，不是真实报价。期权方案的赛马一直在比玩具。
- 改：期权方案一律走 desk/options_v2_backtest.py 的真实报价引擎；algolab 的期权近似只留作历史，不再给分。

## 1. 数据分三段（核心防作弊）
| 段 | 日期 | 谁能看 |
|---|---|---|
| 开发段 | 2024-01-02 → 2025-06-30（含 2024-08、2025-04 两次暴跌） | agents 每轮都能看，打分只用这段 |
| 金库段 | 2025-07-01 → 最近 | agents **永远看不到**；每周最多 1 次晋级考试，由代码执行，结果只给 Opus/人 |
| 前向段 | 从晋级那天往后 | 影子记账 + Alpaca 模拟盘，真实成交价 |
金库考一次 = 全局试验次数 +1（v1 32 + v2 28 起算）。金库结果不回流给提方案的 agent（只告诉它"过/没过"，不给数字），防止 agents 间接拟合金库。

## 2. 每一轮（每天 1 轮，服务器定时；预算走 [agents] budget_day_usd）
1. **提案**：3 个赛马 agent（卖波动派 / 买波动派 / 事件派），各提 1–2 个方案。方案必须是 v2 toml 同款结构（腿、入场过滤、出场），参数只能在允许范围内（见 §4），并写一句经济逻辑 + 引用研究底稿条目。
2. **代码查重**：方案按规范化后的哈希去重；和研究日志里已测过的重复 → 不跑、提案人 −1。
3. **红队**：怀疑派 agent 在回测前读方案，标"可能过拟合 / 偷看未来 / 尾部没封"；风控 agent 估最坏一周。它们的判断事后按金库/前向结果打分（说中了加分）。
4. **回测（代码，不花 token）**：开发段，主口径成交，输出每笔占最大亏损收益、按周块自助 p、Deflated Sharpe、两次暴跌期间持仓盈亏、最差一笔。
5. **打分（代码）**：分 = 开发段 Deflated Sharpe 相对"当前最好方案"的提升（封顶 ±5）− 复杂度罚分（每多一个条件/腿 −0.5）− 暴跌期间亏损超过最大亏损 3 倍的罚分；格式错/越界 −1。
6. **反思（自我迭代）**：每个赛马 agent 读自己的研究日志（提过什么、分多少、为什么），写 ≤300 字 playbook（"哪些方向死了、下一步试什么"），下一轮提案前读它。
7. **淘汰与变异**：沿用 arena.weekly_review（连续两周垫底且落后冠军 ≥10 → 用冠军 playbook 变异出新一代）。

## 3. 每周晋级（周一，代码 + Opus）
- 开发段分数第一、且 DSR > 0、且 PBO < 0.5 的方案，进金库考试（一周最多 1 个）。
- 金库过关标准 = v2 toml [pass] 影子档 + 全局 Bonferroni（0.05/累计试验次数）报告但不强求。
- 过 → 进影子记账（只记账）→ Alpaca 模拟盘 ≥8 周 → 人签字才上钱。不过 → 记入日志，提案人得"金库失败"标记。

## 4. 允许的参数范围（代码校验，超出 = 无效方案）
- 结构：单腿 / 垂直价差 / 跨式 / 宽跨 / 铁鹰 / 铁蝶；每笔 ≤4 条腿；卖出的腿必须有同类型买入腿封顶（不许裸卖）。
- 行权价比例 0.90–1.10（数据只有 ±10%）；到期 14–60 天；出场 exit_dte ≥ 7 且受数据约束。
- 入场条件只能用：IV30/RV20、IV30 历史分位、期限斜率（远月 IV − 近月 IV）、RV20、财报前夜、星期几、v1 的趋势信号；阈值必须是事先给的离散档（例 IV/RV ∈ {0.8,0.9,1.0,1.1,1.2,1.3,1.5}），不许任意小数，减少暗中拟合。
- 每个方案 ≤3 个入场条件。

## 5. "金融 skills"
- 期权专用的开源 Claude skill 目前没有（Anthropic 官方的 financial-services 和社区合集里都没有，R3 已查）。
- 我们自己写成 SKILL.md 格式放 knowledge/skills/，每次开会注入对应角色：
  - options-literature（R1 文献：每种打法的证据、成本后剩多少、尾部）
  - backtest-review（改写自 shakeebshaan 的 backtest-review，MIT，注明出处）
  - tail-risk-checklist（2024-08、2025-04、跳空、提前行权、流动性）
  - position-sizing（凯利、破产概率、为什么不能加倍）
- 开源库：arch（块自助）；PBO/CSCV 自己实现（~50 行，对照 fynance 的公式）；IV 用 v2 引擎自带的 BS（以后可加 py_vollib 对拍）。

## 6. 成本
- 一轮约 3 提案 + 2 红队 + 3 反思 ≈ 8 次调用；赛马用 Haiku、冠军和红队用 Sonnet，预计每轮 < $0.5；仍受 $4/天、$60/月硬上限。
- 回测跑在服务器，内存上限 700MB，不影响真钱程序；不加服务器费用。

## 7. 诚实限制（写进网站页面）
- 开发段只有 18 个月、两次暴跌；agents 再聪明，样本也就这么多。
- 金库每看一次就"用掉"一点：这是为什么一周最多一次。
- 自我迭代提升的是"提方案的质量和速度"，不保证找到能赚钱的方案；找不到就是找不到，循环会如实记录。
